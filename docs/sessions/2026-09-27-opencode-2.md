# Session: 2026-09-27 — opencode — S4.T8

## Goal

S4.T8 (issue 05 of `.scratch/s4-t5-t10-connection-lifecycle/`) — transport
tuning. A new top-level `transport:` config section with four pointer fields and
exported defaults replaces `http.DefaultTransport` on the proxy with a
configured `*http.Transport`: `dial_timeout` (5s), `response_header_timeout`
(30s), `max_idle_conns_per_host` (100), `idle_conn_timeout` (90s). The total
idle pool is sized from the per-host value and the backend count; a reload that
changes `transport` is rejected whole. Spec stories 9–13, 26, 31, 36.

## Design decisions

No ADR: the ticket map marks T8 "none". Every choice is recorded in the spec's
S4.T8 section, the struct doc comments, and `configs/example.yaml`; no new
architecture decision beyond the existing nil-means-omitted convention
(ADR-0011 d10) and the reload non-reloadable-field rule (ADR-0015 d4).

- **Injection via a new additive `Proxy.SetTransport(*http.Transport)`.** The
  frozen `proxy.New(reg, sel)` signature is untouched, mirroring `SetMetrics`.
  `internal/app` builds the transport (it owns the config) and installs it at
  construction time, matching how observers and metrics are wired.
- **`buildTransport` lives in `internal/app`, not `internal/proxy`.** The proxy
  package deliberately does not import `config`; construction needs both the
  config section and the backend count, so it belongs above config.
- **Total `MaxIdleConns = per-host × backend count`.** Operators tune per-host,
  not total (YAGNI); sizing the total from the per-host value is what stops the
  stdlib default of 100 from silently capping a larger per-host setting.
- **`normalizePositiveInt` added alongside `normalizeDuration`.** The
  `max_idle_conns_per_host` knob is the first int-typed config field; the helper
  keeps the same nil-means-omitted / reject-non-positive behavior.
- **`backendKeepAlive = 30s` is a constant, not a knob.** Replacing
  `http.DefaultTransport` would otherwise silently disable TCP keep-alives; the
  value preserves the stdlib default while the operator tunable stays the dial
  bound.

The behavior tests have teeth: the dial test targets TEST-NET-1
(`192.0.2.1:9`, reserved and unroutable) with a 200ms dial bound and observes a
502 in ~0.20s — the 30s stdlib default would fail the `elapsed < 2s` assertion.
The response-header test blocks a backend handler on a channel with a 200ms
bound and observes a 502 in ~0.20s, asserting it waited at least half the bound
(not an instant connection failure).

## Known finding

The two `test/chaos` config builders construct `config.Config` directly;
`reloadChaosConfig`/`chaosConfig` are passed to `App.Reload` **without** calling
`Validate`, so `NonBackendChanges`' transport dereference panicked until each
builder materialized the transport defaults. Same class of fixture debt as T7's
`Server` field — fixed by extending the builders, not by making
`NonBackendChanges` nil-tolerant (its contract requires validated configs, and
every other section already dereferences).
