## What was built

- `internal/config/config.go` — `TLS *TLSConfig` and `H2C bool` on `Config`;
  new `TLSConfig{CertFile,KeyFile}`; `ServerConfig.IdleTimeout`; new
  `DefaultIdleTimeout` (90s); `Validate` rejects `tls`+`h2c` together and an
  empty cert/key, and normalizes `idle_timeout` through the existing
  positive-duration path.
- `internal/config/diff.go` — `NonBackendChanges` names `tls`, `h2c`, and
  `server` (which now includes `idle_timeout`); `tlsConfigEqual` treats a nil
  block as a mode change.
- `internal/app/app.go` — `buildClientServer` loads the cert pair into the
  client server's `TLSConfig` at build time (bad path ⇒ startup error) and
  branches `ReadTimeout`/`IdleTimeout` per mode; `serve` calls
  `ListenAndServeTLS("", "")` when `TLSConfig` is set. The metrics/health
  servers never get a `TLSConfig`, so they stay plain HTTP.
- `scripts/generate-cert.sh` — SAN cert (`localhost`, `lb`, `backend1`–`backend4`,
  `127.0.0.1`, `::1`) written to `certs/server.{crt,key}`; openssl invoked with a
  generated config so SANs work on both LibreSSL and OpenSSL. `/certs/`
  gitignored.
- Tests: `internal/config/config_validate_test.go`
  (`TestValidateListenerMode` + `idle_timeout` rows),
  `internal/config/config_load_test.go` (tls/h2c/idle decode + unknown-field
  rows), `internal/config/diff_test.go` (tls/h2c/idle rows),
  `internal/app/tls_test.go` (build-time cert load, bad path, plain-vs-TLS
  construction, plain operational listeners, and a `Run`-driven ALPN+HTTP/2
  integration test). The test cert is generated in-process so the suite needs
  no openssl.
