## Audit fixes (S1.T2-fix follow-up)

findings; this follow-up addressed the actionable ones, keeping the tree
green throughout.

- **fix(config): reject uppercase URL schemes** — the audit found a real bug:
  `url.Parse` lowercases `u.Scheme`, so `HTTP://host` passed the post-parse
  `http`/`https` check. Validation now requires a lowercase `http://` or
  `https://` prefix on the **raw** string before parsing; the host/query/
  fragment checks are unchanged. Two rejection cases (`HTTP://backend:9001`,
  `HTTPS://backend:9001`) added to the `TestValidate` table (written red-first).
- **test(config): assert example.yaml round-trips** — added `TestExampleConfig`,
  which reads `configs/example.yaml` from disk via a path relative to the
  package directory and runs `Load` + `Validate`, so the shipped example cannot
  drift out of sync with the schema.
- **docs(adr): add ADR-0004 rejecting unimplemented algorithms** — records the
  vocabulary-vs-acceptance distinction (`implementedAlgorithms` is the Sprint 1
  acceptance set), supersedes the frozen constant block's "all four accepted"
  comment, and is indexed in `AGENTS.md`. Rationale: validation encodes "will
  this work?", not "does this parse?".
- **chore: align tracking files** — corrected the PROGRESS S1.T2 Files bullet to
  the split test files, ticked issue 02's acceptance boxes, and completed this
  log's commit list (the missing `refactor(config): table-drive TestLoad cases`).
- **refactor(config): rename loop var and remove scratch reference** — `b` →
  `backend`; `config.go` no longer points at the ephemeral `.scratch/` spec,
  citing ADR-0004 instead.
- **Dismissed findings** (documented, not acted on): `errors.New` for leaf
  errors with no underlying cause (correct Go idiom; the AGENTS.md ban is for
  dynamic messages), and the `validateBackendURL` data-clump shape (not a

## S1.T3 — Implement `internal/backend` (issue 01 of `.scratch/s1-t3-t9-backend-selector-proxy/`)

### Goal
Implement `Backend` (identity, health, active-connection count) and a
concurrency-safe `Registry` behind method-only state access, so the
selectors (S1.T4/T5) and proxy (S1.T6) can read and mutate backend state
safely under concurrent requests.

### Done
- `internal/backend/backend.go`: implemented `IsHealthy` (`healthy.Load()`),
  `SetHealthy` (`healthy.Store`), `IncActive`/`DecActive`
  (`active.Add(±1)`), `ActiveConns` (`active.Load()`); added the
  ADR-0006 `SetHealthy` method and named it in the struct doc's
  method-only-access contract.
- `internal/backend/registry.go`: `Registry` holds an ordered
  `[]*Backend`; `NewRegistry` parses each validated `BackendConfig.URL`
  (wrapping parse errors `backend: parse url ...: %w`), stamps every
  backend healthy, and preserves config order. `All()` returns
  `slices.Clone`; `Healthy()` builds a fresh filtered slice, both
  preserving order.
- `internal/backend/backend_test.go`: replaced the placeholder
  `TestScaffold` with table-free behavior tests — health get/set,
  active-conn inc/dec, 100-goroutine concurrent inc then dec converging
  to 100 then 0, and concurrent health toggling.
- `internal/backend/registry_test.go`: table-driven construction
  (order + URL preservation, single backend, path prefix), invalid-URL
  error, "starts healthy", `All` includes unhealthy, table-driven
  `Healthy` filtering (all/none/one), fresh-snapshot isolation, and a
  concurrent `IncActive`/`IsHealthy`/`SetHealthy`/`DecActive` test.
- Verified: `make test`, `make test-race`, `go vet ./...`, `gofmt -l .`
  clean. Coverage: **100.0%** of statements in `internal/backend`.

### Decisions
- No new ADR: `SetHealthy` was already frozen by ADR-0006, and the rest
  (unexported atomics, ordered slice, fresh snapshots) by ADR-0002 and
  the S1.T3 issue spec.
- Test files split by subject (`backend_test.go` for `Backend`,
  `registry_test.go` for `Registry`) rather than the issue spec's single
  `registry_test.go`; PROGRESS.md's Files bullet was corrected to match,
  consistent with how S1.T2 split `config_load_test.go` /
  `config_validate_test.go`.
- `NewRegistry` still parses URLs rather than trusting config blindly:
  `config.BackendConfig` is a plain struct, so the `(Registry, error)`
  contract has to be honored even though `config.Validate` normally
  guarantees parseability.
