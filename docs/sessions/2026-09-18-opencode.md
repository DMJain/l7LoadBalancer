## S1.T4 — Implement `balancer.RoundRobin` (issue 02 of `.scratch/s1-t3-t9-backend-selector-proxy/`)

### Goal
Implement the first `Selector` implementation: `RoundRobin`, rotating across
the healthy set with a lock-free `atomic.Uint64` counter, so a config using
`round_robin` gets real rotating selection. The `Selector` interface and the
`ErrNoHealthyBackends` sentinel were already frozen in the S1.T0.5 stub, so
this task added no new contract surface — only the counter field and the two
stubbed method bodies.

### Done
- `internal/balancer/roundrobin.go`: added the unexported `counter
  atomic.Uint64` field (documented under the existing concurrency-comment
  convention); `NewRoundRobin` stores the registry; `Select` snapshots
  `reg.Healthy()`, returns `ErrNoHealthyBackends` on an empty snapshot, and
  otherwise returns
  `healthy[(counter.Add(1)-1) % uint64(len(healthy))]`. The `-1` starts
  rotation at the first healthy backend for call #1; unsigned wraparound is
  harmless modulo the length. The two `Implemented in S1.T4` stub markers
  were dropped now that the bodies exist.
- `internal/balancer/roundrobin_test.go` (new, Red first): table-driven
  `TestRoundRobinCyclicOrder` (3 healthy → a,b,c,a,b,c; one unhealthy
  skipped → a,c,a,c; single healthy repeats → a,a,a),
  `TestRoundRobinNoHealthyBackends` (all unhealthy → `errors.Is` matches
  `ErrNoHealthyBackends`), and `TestRoundRobinConcurrentDistribution` (1000
  goroutines, one Select each, per-backend counts within ±5% of 333.3 and
  summing to 1000). A real `backend.Registry` (via `NewRegistry`) is the
  fixture; no mocks.
- Verified: `make test`, `make test-race`, `go vet ./...`, `gofmt -l .` all
  clean. `go test -cover ./internal/balancer/...` reports **46.2%** for the
  package — depressed only because `leastconn.go` (S1.T5) and
  `NewFromConfig` (S1.T7) are still panic stubs; `RoundRobin`'s own paths
  are fully covered (baseline to be re-measured in S1.T8).

### Decisions
- No new ADR: the counter type (`atomic.Uint64`), modulo indexing over the
  fresh `Healthy()` snapshot, and the `ErrNoHealthyBackends` sentinel are
  all already fixed by `docs/design/sprint-1-contracts.md`, ADR-0002, and
  the issue spec. The only choice left open was whether call #1 starts at
  index 0 or 1; chose 0 (`Add(1)-1`) so cyclic-order tests read naturally
  from `backend-a`.
- Distribution test uses one goroutine per Select rather than a shared loop,
  so it exercises concurrent `counter.Add` under `-race` as the spec asked,
  while remaining deterministic in outcome (the atomic counter guarantees
  exact balance at 1000 calls, so there is no flake margin to defend).

## S1.T5 — Implement `balancer.LeastConnections` (issue 03 of `.scratch/s1-t3-t9-backend-selector-proxy/`)

### Goal
Implement the second `Selector`: `LeastConnections`, routing each request to
the healthy backend with the fewest in-flight connections, so a config using
`least_conn` balances by current work rather than turn-taking. Reads
`ActiveConns()` only — the proxy (S1.T6) owns mutation.

### Done
- `internal/balancer/leastconn.go`: `NewLeastConnections` stores the registry;
  `Select` snapshots `reg.Healthy()`, returns `ErrNoHealthyBackends` on an
  empty snapshot, then linear-scans for the lowest `ActiveConns()`. It
  replaces the current best only on a **strictly lower** count, so the first
  backend in registry order wins ties — deterministic and reproducible. The
  `Implemented in S1.T5` stub markers were dropped.
- `internal/balancer/leastconn_test.go` (new, Red first): table-driven
  `TestLeastConnectionsPicksMinimum` (fewest wins; idle preferred; all-equal
  ties → `backend-a`; tie among trailing backends → earlier of the tied;
  unhealthy backend ignored even when idle);
  `TestLeastConnectionsTieBreakIsDeterministic` (10 repeated selects all land
  on `backend-a`); `TestLeastConnectionsDoesNotMutateActiveConns` (counts
  unchanged after 5 selects); `TestLeastConnectionsNoHealthyBackends`
  (`errors.Is` matches `ErrNoHealthyBackends`). Reuses the
  `newTestRegistry`/`setHealthy`/`selectName` fixtures from
  `roundrobin_test.go` (same package), adding a `seedActive` helper that
  stands in for the proxy's `IncActive`.
- Verified: `make test-race`, `go vet ./...`, `make fmt` clean.
  `go test -cover ./internal/balancer/...` rose **46.2% → 77.3%**; the
  remainder is `NewFromConfig` (S1.T7), re-measured in S1.T8.

### Decisions
- No new ADR: the scan, the strict-less-than tie-break, the read-only
  `ActiveConns()` access, and the `ErrNoHealthyBackends` sentinel are all
  already fixed by `docs/design/sprint-1-contracts.md`, ADR-0002, and the
  issue spec.
- Tie-break test uses an all-equal seed and asserts `backend-a` repeatedly,
  rather than probing each pair: it pins the exact "first in registry order"
  rule the contract calls out, and would fail if replacement were `<=`.
