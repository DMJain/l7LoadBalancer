## What was built

- `demo/acceptance.sh` — bash, `set -euo pipefail`, `fail()` naming the
  assertion/LB/values, non-zero exit, EXIT-trap restore, in the
  `observability/smoke.sh` and `chaos/eviction.sh` style.
- It reaches the demo's internal-only ports (LB metrics, generator control
  `:9090`, backend admin `:9091`) by exec'ing busybox `wget` inside the running
  demo Prometheus container (`in_prom`), with stdin closed (`</dev/null`) so an
  exec cannot consume a `while read` loop. It reads Prometheus's HTTP API by
  POST form query (`prom_query`) and parses with `python3`.
- Preconditions: Prometheus ready; `lb-roundrobin`/`lb-p2c-ewma` healthy
  targets; all four backends selectable on both; every backend's profile at
  `sleep_ms=0 jitter_ms=0 fail_rate=0` (read through the admin listener's
  POST-`{}` keep-all form); the eight generators at the fixed check rate.
- Phase 1: `backend3` at 200 ms (jitter 0), wait 30 s, assert from
  `lb_request_duration_seconds_bucket` that `backend3` p50 ≥ 150 ms and
  `backend1/2/4` ≤ 20 ms.
- Phase 2: re-point the generators at `lb-p2c-ewma`, wait 30 s, assert
  `backend3`'s share of `lb_requests_total` < 15%.
- EXIT trap restores every backend profile and every generator's rate and
  target, pass or fail.
- `INJECT_BACKENDS` (default `backend3`) is the negative-run hook: it changes
  which backends phase 1 injects into, while the assertion stays fixed at
  backend3 slow / `backend1/2/4` fast. `demo/README.md` documents the check and
  the hook.

## Evidence

- `bash -n` and `shellcheck -S style` clean.
- On a fresh `up`, the check passed twice in a row — phase 1
  `backend1/2/4 p50=2.5 ms`, `backend3 p50=175.5 / 175.0 ms`; phase 2
  `backend3 share=0.00%`.
- The trap left every backend at `sleep_ms=0 jitter_ms=0 fail_rate=0` and every
  generator at `total_rate=400 target=http://lb-roundrobin:8080`.
- The required negative run (`INJECT_BACKENDS="backend2 backend3"`) exited 1 at
  phase 1 with
  `FAIL: phase 1 [lb-roundrobin]: backend2 p50=175.1ms > 20ms (injected latency is not isolated to backend3)`,
  and the trap restored both backends.
- `make test`, `go vet ./...`, and `gofmt -l .` clean (no Go changed).
- The bench stack was paused only to free `:8080` for the demo, then restarted.

## Decisions

- **Reach internal ports via the Prometheus container.** The demo's generators,
  backends and LB metrics listeners are scratch/distroless images with no shell;
  the Prometheus image is busybox. Exec'ing `wget` inside it keeps every control
  port internal (ADR-0023 decision 2) with no compose change and no extra image.
- **Busybox `wget`, not `curl`.** Spec.md:199 says "curl against the Prometheus
  HTTP API"; the container ships only busybox `wget`. Functionally equivalent;
  flagged by the standards review as a literal mismatch, accepted.
- **`in_prom` closes stdin.** Without `</dev/null`, `docker compose exec` drains
  the caller's stdin, so the restore `while read` loop processed only its first
  line (a real bug found and fixed during verification).
- **`INJECT_BACKENDS` hook.** The negative run needs a second slow backend while
  the assertion stays fixed; the hook is the minimal carrier. Named for what it
  does (injection), not for an expectation it does not change.
- No ADR: the design is fixed by ADR-0023 decision 10 and the bundle spec; the
  script adds no system decision.
