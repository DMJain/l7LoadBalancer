## Decisions

- **Spill uses a 1% share floor, not the literal "more than one backend received
  traffic".** The active health checker probes each backend's *own URL*
  (`internal/health/checker.go`), and every bench config points that at `/`,
  which the dummy backend counts. So every `/stats` delta carries a few probe
  arrivals per backend per window, and the literal rule reads `yes` on every
  run — including Nginx, which the expected shape (issue 13) says does not spill.
  The floor ignores that background; at benchmark rates a real bounded-loads
  spill is far above it. The raw counts stay in the result, so nothing is hidden.
  This is a read-side workaround; the upstream cause (spec instrument story 19
  wants probes excluded, but they are not) is recorded as a proposed ticket, not
  fixed inline. No ADR: benchmark reporting conventions live in the spec.
- **Reads bracket each measured attack.** The acceptance says "every measured
  consistent-hash run … peak and latency", read as each attack: one pair for the
  peak-throughput result, one pair per latency rate. `discover_peak`'s search
  attacks are not measured runs and are excluded.
- **The differ is `arrival_deltas` over two snapshot files.** Both the hot-key
  and the future degraded/drain-reload consumers feed it the same
  `name<TAB>count` format; only the formatting differs.
- **No Go, no backend, no config change.**
