## Done

- `bench/docker-compose.yml`: `cpuset` on every service — `lb`/`nginx` `"0-1"`,
  `backend1`–`backend4` `"2"`–`"5"`, `vegeta` `"6-7"` — with comments tying each

  cores 0–1; backends 1–4: cores 2–5, one each; vegeta: cores 6–7.", to be

- `bench/run.sh`:
  - `verify_lb_gomaxprocs` runs after every LB (re)create (`set_lb`), reads
    `gomaxprocs` from the LB startup line in `docker compose logs` (via the
    existing `json_field` helper), and aborts naming the check and value unless
    2.
  - `verify_nginx_workers <proto>` runs after every Nginx (re)create (`up_h2`,
    `up_http11`, `set_nginx_conf`), waits for a 200 through the listener
    (`wait_target` readiness plus `smoke_ok_200` to reject a 3xx), then counts
    `nginx: worker process` via `compose exec nginx ps` and aborts unless 2.
  - `smoke_proto`'s comment reconciled: `|| true` still covers a compose-up
    failure, but a CPU-pinning mismatch aborts the slice from inside.
- `bench/README.md`: a "CPU pinning and run-time checks" section documents the
  split (verbatim sentence) and both checks.

  hoisted into a YAML anchor; two services do not justify an anchor, and each

## Open items / handoff notes

- The harness reads `gomaxprocs` from the LB's container logs, so the `lb` image
  must be current. `docker compose up` does **not** rebuild; a stale image
  predating S5.T5.6 makes the check abort with `gomaxprocs=unknown`. In normal
  use this is fine because `make bench-repro` builds the images first (S5.T12);
  a bare `./bench/run.sh smoke` on a machine with an old image needs `docker
  compose -f bench/docker-compose.yml build` once.
