## Design decisions

- **Drop the URL from every branch, structurally** — the scheme/host/query/
  fragment branches already name the backend and the field; only their extra
  `%q` URL argument is removed. The messages become, in order: "must use http or
  https scheme", "has an invalid url", "must include a host", "must not include
  a query string", "must not include a fragment".
- **The parse branch does not wrap `url.Parse`'s error** — `url.Parse` wraps
  its cause as `parse "<raw>": <cause>`, so a `%w` would re-introduce the raw
  URL. The cause alone is not safe either: for `http://host:80a` it is
  `invalid port ":80a" after host`, which embeds a fragment of the resolved
  value. There is therefore no URL-free cause to wrap, and the branch reports
  only "has an invalid url". This is a deliberate, documented exception to the
  frozen wrapping convention (`docs/design/sprint-1-contracts.md`: "Wrapped
  errors via `fmt.Errorf("<pkg>: %w", err)` throughout") forced by the security
  requirement; no branchable sentinel is introduced. The code comment on
  `validateBackendURL` records the exception.
- **No ADR** — the redaction was locked in the grilling (spec, "Redaction
  (grilling Q6, landed)") and the ticket calls for no ADR; the wrapping
  exception is recorded here and in the code comment rather than as a new
  decision record, to stay inside the ticket's scope (AGENTS.md Step 2.5).

## Registry parse error is unreachable (the structural argument)

`internal/backend/registry.go:88` (`newBackend`) calls `url.Parse(cfg.URL)`, and
its error message embeds the raw URL. No change is needed there for
config-sourced URLs, for three composable reasons:

1. `app.Build`'s contract states "cfg must already have passed Validate"
   (`internal/app/app.go`), and main runs `config.Load` then `cfg.Validate`
   before calling `Run`/`Build` (`cmd/l7LoadBalancer/main.go`).
2. `validateBackendURL` already runs `url.Parse(raw)` and rejects any parse
   failure, so by the time a URL reaches the registry it has already parsed
   once. A string that parsed in `Validate` parses again in `newBackend`.
3. The registry is reachable with unvalidated config only from tests that
   deliberately call `backend.NewRegistry` directly, not from the production
   path.

So the registry's URL-bearing error remains, correctly, as a defensive
unreachable branch. If a future caller ever builds a registry from unvalidated
config, that error would be the place to revisit — recorded here as the
handoff note rather than pre-emptively changed.
