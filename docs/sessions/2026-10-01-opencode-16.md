## Decisions

- **The JSON report is the percentile source, as the ticket says.** The harness
  not committing one was a gap; the additive one-line `cp` in `save_result`
  closes it without changing any existing `.txt`/`.hdr` output. The published run
  (T6) has not happened, so no recorded data is invalidated. The `.txt` header
  stays the metadata source because `peak_rps` (the discovered peak) is not in
  the JSON report.
- **The harness change is in scope for T10.1.** The ticket's stated data source is
  the JSON report; without emitting one the generator could not run on the
  published run's raw output, which is its whole purpose. It is the minimum
  change that makes the ticket's own approach functional.
- **The fixture test proves the source, not just the values.** Because the `.txt`
  text report carries the same percentiles, a value-only assertion would pass if
  the parser regressed to text. The test perturbs one JSON percentile and watches
  the cell follow.
- **No new ADR.** The spec records the methodology; there is no hard-to-reverse,
  surprising, real-trade-off decision here (spec *Decisions explicitly not taken*).
