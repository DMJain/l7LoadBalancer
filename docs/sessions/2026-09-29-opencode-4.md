## Implementation notes

- **The `ForceAttemptHTTP2` gotcha (spec §17).** `buildTransport` must set
  `ForceAttemptHTTP2` explicitly: Go auto-negotiates HTTP/2 only when
  `TLSClientConfig` is nil, and `tls_skip_verify` sets it — otherwise every
  `https://` backend silently falls back to HTTP/1.1 with no error. The field
  is set unconditionally from `force_http2`, and the test asserts h2 is kept
  when a custom `TLSClientConfig` is present.
- **`ForceHTTP2` is a `*bool` because its default is true** — nil ("omitted")
  must be distinguishable from an explicit `false`. `TLSSkipVerify` stays a
  plain `bool` because its default (false) is the zero value, so no defaulting
  code is needed. The default is applied in `normalizeAndValidateDefaults`
  (renamed from `normalizeAndValidateDurations`, which already defaulted the
  `max_idle_conns_per_host` int, so the old name was already imprecise).
- **`protocol` source.** The ticket says source `req.Proto`, but `req.Proto` is
  `"HTTP/2.0"` for both h2 and h2c, so it cannot separate the two label values.
  `protocolLabel` uses `r.ProtoMajor` plus TLS presence (`r.TLS != nil` → `h2`,
  else `h2c`), which is a necessary and documented refinement. The vocabulary is
  a typed closed set (`metrics.ClientProtocol`) matching the `CircuitState`
  precedent; HTTP/1.0 is folded into `http/1.1` to keep it closed at three.
- **Metric scope.** `protocol` rides the request counter only (spec §19); the
  duration histogram keeps `backend`/`method`/`status_class`.
- **`backend_proto`** is captured from `resp.Proto` in `modifyResponse` into
  `reqState` and added to the existing "request complete" line, absent when no
  response arrived. `reqState` stays single-goroutine (ADR-0007).
