## Done

- `main.go` gains a `statsResponse` struct (`backend`, `requests`). `newHandler`
  holds `var arrivals atomic.Int64` as a closure variable — one process, one
  backend container, so a single atomic is the whole story.
- `GET /stats` returns 200 with `{"backend":"<name>","requests":<n>}` read via
  `arrivals.Load()`. It sits with `/health` as a control endpoint: it returns
  before the increment and so bypasses `SLEEP_MS`/`FAIL_RATE`.
- The increment, `arrivals.Add(1)`, is the first action on the benchmark path —
  after the 405, `/health` and `/stats` early returns, and before the injected
  sleep and failure decision. A request still in flight is already counted.
- The package doc comment gains the concurrency note: `net/http` is
  goroutine-per-request, the arrival counter is the only shared mutable state,
  and `math/rand/v2`'s top-level functions are concurrency-safe. `newHandler`'s
  doc comment now names `/stats` alongside `/health`.

## Decisions

- **Atomic, not a mutex-guarded map.** The ticket and spec both fix this: one
  process per backend container means one counter; a map keyed by path would be
  unnecessary state.
- **`/stats` orders after `/health`, both before the increment.** The cheapest
  way to satisfy "first action before sleep" and "exclude the control
  endpoints" simultaneously is to handle the two control paths first, then
  increment once for everything that remains. The 405 branch also returns first,
  so a non-GET is not an arrival.
- **`/stats` logs like `/health`.** Consistent with the existing control
  endpoint; the harness reads it rarely, so it is not part of the
  throughput-ceiling concern that turned bench logging off.
- **No new ADR, no request-path change.** Per the spec.
