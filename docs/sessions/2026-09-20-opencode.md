## Decisions

- **ADR-0010 written in the Design step, before code** (AGENTS.md Step 2.8), so
  the `Backend`-owned-latency, cold-start, and failure-penalty decisions have a
  durable record independent of the untracked `.scratch` spec. The Evidence
  section was added after the test ran, carrying this task's own recorded
  numbers, the same way ADR-0009 did.
- **The measurement window is the backend round trip only, and that is a
  second timestamp.** `director()` → `modifyResponse`, not the
  `ServeHTTP`→body-close window `latency_ms` measures. Reusing `start` would
  have made a slow client look like a slow backend to P2C.
- **Failure records a flat 2s, not elapsed time.** With a fast failure
  (connection refused) the real elapsed time would be near-zero and P2C would
  treat the failing backend as the *fastest* one — a wrong-signed signal. 2s
  dominates the committed 50/150/300ms dummy latencies; the ADR notes `SLEEP_MS`
  has no enforced ceiling, so the margin is a deliberate headroom choice, not
  an assumed bound.
- **Two random indices via `rand.IntN` package functions, not a
  `*rand.Rand`.** A per-selector RNG would need its own mutex, undercutting the
  lock-free CAS-based `RecordLatency`/`EWMALatency` design. The distinct-index
  draw (`j` in `[0,n-2]`, incremented past `i`) is the standard unbiased
  two-sample-without-replacement construction.
- **Tie-breaking is arbitrary.** Unlike `LeastConnections`, two EWMA values
  derived from different floating-point histories are not a
  reproducible-by-design tie, so no registry-order rule is promised (matching
  the spec).
- **The load-skew test uses four backends, not two.** With two healthy
  backends both are always sampled, so the test degenerates to "always the
  faster" — true, but no sampling is visible. Four backends shows the real
  property: the fast backend is drawn half the time and lands ~50% of requests
  while each slow peer gets ~1/6. The two-backend deterministic case is still
  pinned separately (`...PrefersFasterOfTwo`).
- **A `t.Logf` in the load-skew test records the actual split** (one run:
  fast 2,043/4,000 = 51.1%, slow 671/647/639) so the property's numbers are
  visible under `-v` and mirrored in ADR-0010, rather than asserted only as a
  bound.

## S3.T0.2 — Round-trip observer fan-out (issue 02)

Second Sprint 3 task: a prefactor that replaces the proxy's single hardcoded
`state.backend.RecordLatency(...)` call with a generic `RoundTripObserver`
fan-out, so S3.T2 (passive outlier detection) and S3.T3 (circuit breaker) can
each register a listener with zero further changes to `proxy.go`'s hook logic.
Shape pinned by ADR-0011 decision 9; no new ADR. TDD per `AGENTS.md`.

### What was done

- `internal/proxy/proxy.go`:
  - New consumer-defined `RoundTripObserver` interface —
    `ObserveRoundTrip(b *backend.Backend, d time.Duration, success bool)` —
    with a doc comment recording the "recording is unconditional; gating is
    conditional" rule and why an early-return guard would be wrong.
  - `Proxy` gains an unexported `observers []RoundTripObserver` slice and an
    additive `RegisterObserver(o RoundTripObserver)` method; `New(reg, sel)`'s
    frozen two-argument signature is untouched. Registration is documented as
    construction-time-only (slice read on the request path without a lock).
  - New `observe(state, d, success)` helper is the single fan-out path.
  - `modifyResponse` computes `success := resp.StatusCode < 500` and
    `d := time.Since(state.dispatchStart)`, then fans out.
  - `errorHandler` fans out `success = false, d = p2cFailurePenalty`.
  - The old direct `RecordLatency` call becomes unexported `latencyObserver`,
    exposed to `main` through `NewLatencyObserver() RoundTripObserver`. It
    ignores `success` because the duration it receives already encodes the
    failure penalty on the error path — preserving the pre-fan-out behavior
    exactly (real duration on a 5xx that reached the backend, fixed penalty on
    a transport failure).
- `cmd/l7LoadBalancer/main.go`: new `newHandler(reg, sel)` helper constructs
  the proxy and registers `proxy.NewLatencyObserver()` before the server
  starts; `main` uses it as the `http.Server.Handler`. Doc comments note that
  Sprint 3's other two observers register in the same place as they land.
- `internal/proxy/proxy_test.go`:
  - `spyObserver` records every invocation and optionally delegates to an
    `inner` observer, so an observer whose side effect is not countable (the
    latency adapter's EWMA write) can still have its call count asserted.
  - Three new tests, each registering the latency adapter (wrapped) plus a
    plain spy and asserting **count** (`require.Len(..., 1)`):
    `...OnceOnSuccess` (2xx, `success=true`, non-zero duration),
    `...OnceOn5xx` (5xx response, `modifyResponse` path, `success=false`),
    `...OnceOnConnectionRefused` (`errorHandler` path, `success=false`,
    `d == p2cFailurePenalty`).
  - The two existing latency-recording tests now register
    `NewLatencyObserver()`, keeping the same assertions/outcomes.

### Decisions

- **`main.go` registers the latency adapter, following ADR-0011 literally.**
  The slice starts empty in `New`; the composition root wires all three
  observers. The cost is that `New()`-only callers no longer record latency,
  which is why the two existing latency tests were updated to register it.
  The alternative (auto-register inside `New`) was rejected because both the
  ADR and the ticket say `main.go` registers it, and a single composition root
  is the more defensible wiring story for the two observers S3.T2/T3 will add.
- **`NewLatencyObserver()` constructor over an exported adapter type.** It
  returns the `RoundTripObserver` interface and keeps `latencyObserver`
  unexported, matching the repo's `NewX` constructor style (`NewRoundRobin`,
  `NewRegistry`, `NewFromConfig`).
- **A wrapping recorder instead of a second bespoke counter.** One
  `spyObserver` type with an optional `inner` covers both a plain spy and a
  counted latency adapter, so the "exactly once" assertion is uniform.
- **The latency adapter ignores `success`.** Preserving behavior was the
  ticket's explicit requirement, and the failure penalty is already carried in
  `d`; having the adapter branch on `success` would smuggle policy back into a
  dumb adapter.

their validation rules before S3.T1 (active health checks) and S3.T3 (circuit

### What was done

    (`cooldown`) types; `Config` gains `Health`/`Circuit` fields. Each duration
    is a `*time.Duration`, documented at the declaration: a plain

    `Validate` could only either silently default an explicitly invalid value
    or reject an omitted one.
  - `Validate` calls a new `normalizeAndValidateDurations` last: nil → apply
    the exported default; non-nil and `<= 0` → `config: <field> must be
    positive, got <d>`. Fail-fast order comment updated to

- Tests (Red-first against undefined `Health`/`Circuit`/default constants):
  - `config_validate_test.go`: omitted durations fall back to the exported
    defaults; explicit values are kept; six rejection cases (zero and negative
    for each of the three fields); new `configWithSprint3YAML` helper.
  - `config_load_test.go`: explicit durations decode from Go duration strings
    (`"1500ms"`, `"250ms"`, `"10s"`) with `Load` still defaulting nothing
    (omitted durations left nil); nested unknown-field typos in `health:` and
    `circuit:` are rejected, proving `KnownFields(true)` strictness at depth.
  - `TestExampleConfig` continues to pass untouched, proving a currently
    committed config still loads and validates unmodified.
- `PROGRESS.md`: S3.T0.3 added and flipped to `[DONE]`; session-log entry
  added. Issue 03's boxes ticked.

### Decisions

- **Nested `health:`/`circuit:` sections over flat top-level fields.** The
  spec calls for "a new global section" for probe interval/timeout; grouping
  circuit's cooldown the same way keeps the two Sprint 3 subsystems legible in
  the schema and leaves room for later keys without flat-name prefixes.
- **`*time.Duration` fields, not a custom set-tracking duration type.** The
  ticket requires rejecting an *explicitly set* non-positive value while
  defaulting an omitted one; nil-vs-non-nil is exactly that signal, and yaml.v3
  already decodes duration strings into `time.Duration` (verified in
  `gopkg.in/yaml.v3@v3.0.1`'s decoder), including through a pointer. A plain
  value would make the two cases indistinguishable; a custom `UnmarshalYAML`
  type would need its own parsing path for no gain.
- **Defaults applied in `Validate`, not `Load`.** `Load`'s documented contract
  is pure deserialization, and the existing `Load` tests assert it defaults
  nothing (e.g. empty algorithm stays empty). Seeding defaults before decode
  would have made durations the sole exception to that contract.
- **No new ADR.** The config-vs-constant split is ADR-0011 decision 10; the
  remaining choices are field-level and documented at their declarations, per
  the ticket's explicit "at the implementer's discretion".
- **No extra cross-field rule (timeout < interval).** Not requested; an
  operator may legitimately choose otherwise. The default relationship is
  documented on `DefaultProbeTimeout` instead.

## S3.T1 — Active health checks (issue 04)

First of the three Sprint 3 subsystems. `internal/health` was an empty stub;
this ticket builds the active half — one probe goroutine per backend and a
consecutive-outcome state machine driving `Backend.MarkHealthy()` /
`MarkUnhealthy()`, started from `main.go` on the shared `sigCtx`. The
composition model (which subsystem may write `healthy`, why probes use the
backend URL and not a health path, why 3xx is a failure, why the thresholds
are constants) is already fixed by ADR-0011; this ticket implements it. The
remaining Sprint 3 half, passive outlier detection (S3.T2), is a separate
ticket.

### What was done

- `internal/health/checker.go` (new; the `health.go` stub comment is removed):
  - `Checker` holding the registry, interval, and a dedicated `*http.Client`;
    `New(reg, interval, timeout) *Checker`.
  - The client's `CheckRedirect` returns `http.ErrUseLastResponse`, so a 3xx
    is observed as a failure rather than followed — without it Go's default
    client follows up to 10 redirects and a redirecting backend would probe
    as healthy. Its `Timeout` is the probe timeout; no transport is shared
    with `internal/proxy`.
  - `Start(ctx)` launches one goroutine per backend. `run` is the ticker
    `for { select }` loop only; all outcome logic lives in `prober.probeOnce`,
    which tests call directly.
  - `probeOnce`: success → zero the failure run, grow the success run, call
    `MarkHealthy` at M; failure → zero the success run, grow the failure run,
    call `MarkUnhealthy` at N.
  - `probe`: GET `backend.URL.String()` via the client, drain the body, and
    report `2xx` only. Transport errors and non-2xx are failures.
  - Constants `probeFailuresBeforeUnhealthy` (3) and
    `probeSuccessesBeforeHealthy` (2), with rationale for the values inline.
- `cmd/l7LoadBalancer/main.go`: constructs the checker from
  `*cfg.Health.ProbeInterval` / `*cfg.Health.ProbeTimeout` and calls
  `Start(sigCtx)` right after the `signal.NotifyContext`, logging the two
  intervals; `main`'s doc comment updated.
- Tests (Red-first against undefined `New`/constants, confirmed build failure):
  response-class table (200/204/299 pass; 300/404/500 fail); redirect observed
  not followed (a 302 whose target answers 200); connection refused; 5xx and
  connection-refused each eject after N with the N-1 boundary checked;
  consecutive successes reinstate after M with the M-1 boundary checked;
  an intervening success resets the failure run; the dedicated client's
  timeout bounds a probe (short timeout fails, generous succeeds); a malformed
  URL fails rather than panicking; and `Start` probes every backend and stops
  on cancellation.
- `docs/architecture.md`, `CONTEXT.md`: component row, new "Active health
  checking" subsection, stale header/not-here-yet entries, and the `Probe`
  glossary entry extended with the thresholds and the single recovery path.
- `PROGRESS.md`: S3.T1 added and flipped to `[DONE]`; session-log entry added.
  Issue 04's boxes ticked.

### Decisions

- **`New(reg, interval, timeout)`, not `New(reg, cfg)`.** Keeps `internal/health`
  depending only on `internal/backend` (the package graph in AGENTS.md), and
  keeps the checker agnostic of where its two durations came from. `main` reads
  them off `cfg.Health`, so the "read from Config" requirement is met at the
  wiring layer.
- **`CheckRedirect` returning `http.ErrUseLastResponse`.** Required, not
  cosmetic: the ticket's "3xx is a failure" rule cannot hold with the stdlib
  default client, which would follow the redirect and see the target's 2xx.
  The test redirects to a live 2xx endpoint specifically so the follower
  behavior would fail it.
- **Per-backend `prober` value, counters unsynchronized.** Each prober is
  touched by exactly one goroutine (or one test), so the counters need no
  atomic; the shared state they act on (`Backend.healthy`) is atomic-backed.
  A per-backend struct also keeps each backend's consecutive run independent,
  which a single shared counter map could not without a lock.
- **N = 3, M = 2.** At the 5s default interval that ejects in ~15s and
  reinstates in ~10s: fast enough for the Sprint 3 exit criterion, slow enough
  not to flap on one lost probe. Values are inline-commented; like ADR-0010's
  α they are tuning constants judged not to clear the ADR bar, and ADR-0011
  decision 10 already fixes that they are constants rather than config.
- **Drain the probe response body.** Lets the dedicated client reuse the
  connection across probes; the client timeout still bounds a slow or endless
  body.
- **No `Stop`/`Wait`.** The ticket explicitly forbids a second shutdown
  primitive: the goroutines exit on `sigCtx.Done()`.
- **No new ADR.** Composition is ADR-0011; this ticket's remaining choices are
  field-level and documented at their declarations.
