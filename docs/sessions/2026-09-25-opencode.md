# Session: 2026-09-25 — opencode — S4.T0

## Goal

S4.T0 (issue 02 of `.scratch/s4-t0-t4-reload/`) — the application seam: a
behaviour-preserving prefactor that moves the whole wiring graph out of `main`
into a new, importable `internal/app` package so production, the chaos harness,
and tests build the system the same way, closing the Sprint 3 retro's
`assemble` duplication debt. Spec stories 48–50, decisions D3–D4.

## Orientation

Read `AGENTS.md`, `PROGRESS.md`, `MILESTONES.md`, the bundle spec, and ticket
02. Confirmed S4.T0 was `[TODO]` (not claimed by another agent) and only
blocked by S4.D0, which is `[DONE]`. Read `cmd/l7LoadBalancer/main.go`,
`cmd/l7LoadBalancer/main_test.go`, and the whole `test/chaos` harness to see
exactly what the app seam had to preserve.

## Scope boundary (AGENTS.md Step 2.5)

- **In scope:** ticket 02's eight acceptance boxes only — `internal/app`
  `Build`/`Run`, the exposed handler/collector/registry, unchanged wiring,
  `main` reduced to flags/probe/load/validate/build/run, the chaos harness
  delegating to `Build`, one build-level routing/seeding test, and the
  `AGENTS.md` graph + directory-map update.
- **Out of scope, deliberately not built:** everything T1–T4 — config diffing,
  ADR-0015, the registry snapshot swap/apply, checker add/remove, outlier
  forget, series deletion, the reload operation, the SIGHUP loop, drain
  config/context, ADR-0016, and the exit-criterion tests. No reload operation
  exists in `internal/app` after this ticket.

## Done

- Task: S4.T0 (issue 02), recorded in `PROGRESS.md` as `[DONE]`.
- Claim commit: `cc0c777` (`chore(progress): start S4.T0 application seam`).
- New `internal/app/app.go`: `Build(cfg, log) (*App, error)` performs the whole
  wiring graph unchanged (collector; seeded registry; breaker installed as
  registry gate and registered as observer; selector from config; proxy with
  metrics plus the latency, outlier, and circuit observers; active checker;
  health-endpoint handler) and returns an `*App` exposing `Handler()`,
  `Collector()`, `Registry()`. `App.Run(ctx)` starts the checker on `ctx`,
  serves the client, metrics, and health-endpoint servers, and on `ctx`
  cancellation gracefully shuts them down in that order under the same 10s
  timeout `main` used. No reload operation.
- New `internal/app/app_test.go`: build-level routing test (requests through
  `Handler()` reach both configured backends), build-level seeded-series test
  (all three gauge families materialized for every backend), a registry
  accessor test, a `Run`-stops-on-cancel test, and the three `seedMetrics`
  unit tests moved from `cmd`.
- `cmd/l7LoadBalancer/main.go` reduced to flags → `probe` short-circuit →
  `config.Load` → `cfg.Validate` → `app.Build` → startup log → `app.Run` on
  the SIGINT/SIGTERM context. `seedMetrics` and `newHandler` deleted. Startup
  log lines unchanged and in the same order.
- `test/chaos/assemble_test.go` now builds through `app.Build` and starts the
  checker by calling `app.Run` in a goroutine cancelled at cleanup; the
  `assembly` handle and every chaos assertion are unchanged. The harness sets
  the metrics and health-endpoint listens to `:0` so `Run` never binds a fixed
  port. `helpers_test.go`'s package doc updated to name the new seam.
- `AGENTS.md`: dependency graph inserts `internal/app` above `proxy`, a new
  `internal/app` component section, the directory-map row, and the
  `cmd/l7LoadBalancer/main.go` entry corrected (it had been stale since
  Sprint 3).

## Decisions

- **`Run` is a method on `*App`, not a free `Run(ctx, cfg)`.** The spec's chaos
  comment had suggested `Run(ctx, cfg)`, but the application value already owns
  the graph and T3 adds a `Reload` method to it; methods keep one lifecycle
  owner. The chaos comment is in a test file, not a frozen contract.
- **`main` emits `l7LoadBalancer starting`.** `Build`'s frozen signature is
  config + logger (no config path), and the line carries the config path; main
  has it. It is emitted after `Build` returns, preserving the old ordering
  (build failure → no `l7LoadBalancer starting` line).
- **`Run` logs its own server/shutdown failures and returns the error; main
  only owns the exit code.** This preserves the old per-server log labels
  (`server error`, `metrics server error`, `health server error`, the three
  shutdown labels) while removing `os.Exit` from a library.
- **The chaos harness calls `Run` in a goroutine.** The checker lifecycle is
  owned by `Run`, and the ticket exposes only handler/collector/registry, so
  this is the only way to start probing without adding surface. Binding `:0`
  for the two auxiliary listeners keeps the harness port-free.

- `go test ./...` and `go test -race ./...` green (macOS `ld` malformed

## Review (two-axis, post-implementation)

Both axes ran against `2b8e9bb...HEAD` (the code commit is `0766bf7`).
Spec axis: conformant, no scope creep (grep of the whole diff found no
reload/diff/apply/snapshot/swap/drain/SIGHUP code). Standards axis found one
hard violation and several judgement calls. Acted on:

- **Error wrapping (hard):** `Build`'s errors now carry the `app:` package
  prefix per the frozen `fmt.Errorf("<pkg>: ...: %w", err)` convention, and the
  selector error keeps `main`'s `algorithm` value in the message.
- **Stale reference created by the move (spec):** `internal/proxy/proxy.go`'s
  `New` doc comment pointed at `main`'s deleted `newHandler`; it now points at
  `internal/app`'s `Build`.
- **Server-error path (both axes):** `Run` now shuts all three servers down

- **Concurrency model (standards):** added the missing model note to `Run`.
- **Data clump / duplicate handler (standards):** `App` stores the validated

- **Test-seam side effect (standards):** the `:0` metrics/health-endpoint

`seedMetrics` unit tests (the ticket explicitly requires the build-level test),

## Decisions

- **The two functions live in `internal/config`, not `internal/app` or a new
  package.** The diff operates purely on `*config.Config`, `internal/backend`
  already imports `config` (so T2's apply can take a `config.BackendDiff`
  without a cycle), and the spec calls the work "config diffing". Package
  graph stays acyclic.
- **`resolved*` re-defaulting was removed after review.** The first cut
  re-applied `Validate`'s defaults inside `NonBackendChanges` so omitted and
  explicit defaults compared equal even with unvalidated input. That
  contradicts the frozen `config.go` contract ("after Validate returns nil,
  every field is populated … downstream consumers never re-check or re-default")
  and ADR-0015 decision 3 ("validated configs"); the nil branches were
  unreachable in every tested path. The direct field comparison now relies on
  `Validate` having materialized every default, and the doc comment states the
  precondition.
- **No separate Red-phase test commit.** Unlike Sprint 1's stubs, these
  functions had no frozen signature to compile against, so a test-only commit
  would not have built. Tests and implementation landed in the single atomic
  commit (AGENTS permits this); the Red state was confirmed by running the new
  tests against the absent functions (`undefined: DiffBackends` /
  `NonBackendChanges`) before implementing.
