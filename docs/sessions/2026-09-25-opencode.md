## Decisions

- **`Run` is a method on `*App`, not a free `Run(ctx, cfg)`.** The spec's chaos
  comment had suggested `Run(ctx, cfg)`, but the application value already owns
  the graph and T3 adds a `Reload` method to it; methods keep one lifecycle
  owner. The chaos comment is in a test file, not a frozen contract.
- **`main` emits `l7LoadBalancer starting`.** `Build`'s frozen signature is
  config + logger (no config path), and the line carries the config path; main
  has it. It is emitted after `Build` returns, preserving the old ordering
  (build failure → no `l7LoadBalancer starting` line).
- **`Run` logs its own server/shutdown failures and returns the error; main
  only owns the exit code.** This preserves the old per-server log labels
  (`server error`, `metrics server error`, `health server error`, the three
  shutdown labels) while removing `os.Exit` from a library.
- **The chaos harness calls `Run` in a goroutine.** The checker lifecycle is
  owned by `Run`, and the ticket exposes only handler/collector/registry, so
  this is the only way to start probing without adding surface. Binding `:0`
  for the two auxiliary listeners keeps the harness port-free.
