## Implementation notes

- **`/health` bypasses `SLEEP_MS`/`FAIL_RATE`.** The ticket calls it "for the LB
  health checker". A chaos-injected failure rate on the probe would make the LB
  flap, so the endpoint is always-200 and cheap. Payload endpoints still honour
  both knobs (locked by `TestHealthBypassesChaos`). The LB's active checker
  probes each backend's *root* URL, not a configured path (ADR-0011 decision
  11), so `/health` is not currently targeted by it; adding a health path would
  contradict that ADR and is out of scope. The endpoint is built as the ticket
  requires and is a general-purpose probe target.
- **TLS is a presence pattern, not a mode flag.** `tlsFilesFromEnv` reads both
  vars: both set → `ListenAndServeTLS`; neither → `ListenAndServe`; exactly one
  set → loud startup error, matching the `envInt`/`envFloat` fail-loudly style.
  `server.TLSNextProto` is left nil on purpose — setting an empty map silently
  disables server-side HTTP/2 (spec §20).
- **Payloads are package-level slices**, built once at init so a benchmark
  measures transport, not allocation. Sizes are exact: 200 B, 10 KiB (10240),
  1 MiB (1048576). The ticket says "10 KB"/"1 MB"; the conventional KiB/MiB
  interpretation is used and the exact byte counts are asserted.
- **Compose keeps one network** (the compose default bridge; no custom network
  block, so nothing can drift onto a second network). Only `lb` and `nginx`
  publish ports; backends and vegeta stay internal. The four backends share a
  YAML anchor carrying the optional `TLS_CERT_FILE`/`TLS_KEY_FILE` env vars and
  the `/certs` mount, so the h2 slice can make them serve TLS without editing
  four services.
- **Vegeta image is built, not pulled.** The common `peterevans/vegeta` image is
  amd64-only; on this arm64 Mac it ran under emulation, which would cap
  throughput at the load generator and distort every published number. A
  multi-stage `bench/vegeta/Dockerfile` pins `vegeta/v12@v12.13.0` and builds it
  for the host arch (verified `aarch64`). The image's entrypoint is overridden
  to `sleep` so `up` leaves it idling; a real run uses
  `docker compose run --entrypoint vegeta vegeta ...`.
- **Config selection for the h2 slice** is two compose env defaults
  (`LB_CONFIG`, `NGINX_CONF`) rather than a second compose file, so the
  topology stays single-source. No new ADR: the vegeta-over-wrk decision and
  its record are issue 06's ADR-0020; the infra choices here are the spec's
  §22–§26.

## Review

Two-axis review (Standards + Spec) at fixed point `cc888ea`, both sub-agents in
parallel. Findings and dispositions:

- **Spec, real gap — backend TLS not reachable from compose.** Fixed: the
  backends now take `BACKEND_TLS_CERT_FILE`/`BACKEND_TLS_KEY_FILE` (empty →
  plain) and mount `../certs`, so the h2 slice can enable LB→backend HTTP/2.
  Verified live (TLS backend returns `HTTP/2.0`).
- **Spec, model mismatch — `/health` vs the LB probe.** Not a code defect: the
  LB probes each backend's root by ADR-0011 decision 11; adding a health path is
  out of scope. Recorded above.
- **Spec, judgement — "all services healthy".** Only `lb` has a meaningful
  healthcheck (the backend image is scratch; it ships no shell to probe with).
  `up` was verified live: all containers up, `lb` healthy, traffic served.
- **Spec, judgement — Nginx keepalive per-worker nuance.** `keepalive 100` is
  the matched configured pool size; nginx scales it per worker while the LB's
  `max_idle_conns_per_host` is flat per host. Pinning one worker would match the
  aggregate but nerf nginx's CPU use, so the configured number is matched and
  the nuance is commented in both configs for issue 06's methodology doc.
- **Standards, judgement — duplicated Nginx upstream/location blocks.** Kept:
  spec §26 asks for two readable configs and a reviewer can audit either alone;
  an `include` adds indirection for a benchmark artifact.
- **Standards, judgement — compose repeats the image HEALTHCHECK.** Kept for
  consistency with the repo-root demo compose, which does the same deliberately.
- **Standards, judgement — `wantLen: -1` sentinel in the test table, four
  `logRequest` call sites.** Left as-is; test-table and pre-existing patterns,
  not worth churn.
