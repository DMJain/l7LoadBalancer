## Design decisions

No ADR: the ticket map marks T10 "none"; the deliverable is a test.

- **Reloads drive `App.Reload` directly, not a real SIGHUP.** The app seam is
  the spec's chosen seam, and the signal registration is the one line the bundle
  explicitly leaves untested. Documented in the test's doc comment.
- **Four backends warm from the start.** The reload phase alternates 3-subsets
  (remove one, add another). A reserve that entered only at reload time would
  bring a fresh transport connection pool that the baseline never saw and
  misread it as growth. Four names is the harness's limit.
- **Both measurements are taken in the same idle state.** After warmup the load
  pauses and the proxy's idle connections drain (short `idle_conn_timeout`),
  then the baseline is captured; the final measurement follows the quiet phase
  the same way. This removes connection-pool churn from the goroutine delta.
  The first attempt (`MaxIdleConnsPerHost=1`) was wrong: it forced a new
  connection per request and exhausted ephemeral ports (`EADDRNOTAVAIL`),
  breaking the death phase's reinstatement.
- **The soak discards logs.** The capture handler retains a record per request;
  over an hour that is itself a heap leak and would fail the soak's own
  assertion. `assembleWith` was split out of `assemble` so the soak can pass a
  discarding logger.
- **Race variant via the `race` build tag.** `soak_race_test.go` /
  `soak_norace_test.go` set `raceDetectorEnabled`; under `-race` the heap
  assertion is dropped (race's memory overhead makes it meaningless) and the
  goroutine assertion kept.

## Review findings applied

A two-axis review (`353a462...HEAD`) flagged: the phases double-counted the
quiet window so a "one-hour" run overran by ~a minute (fixed: the quiet period
is reserved off the budget first, then the four phases split the remainder in
the spec's 2:1:1:1 ratio); and `soakRequest`'s non-cancel branch re-implemented
`doRequestPath` (fixed: delegate). Remaining findings were judgement calls left
as-is (type-level concurrency doc, scenario-specific handlers living with their
scenario, SIGHUP wording).
