## Design decisions

- **Comments, not live template URLs.** `TestExampleConfig`
  (`config_load_test.go`) round-trips the shipped `example.yaml` through the
  real `Load`+`Validate`, and `main` defaults to it, so a live `${...}` would
  break both unless the environment were set. The interpolation examples
  therefore live in the `backends:` comment block, exactly as the
  `reload.drain_window` precedent documents a feature in place. The file's own
  three URLs stay literal and the doc says so.
- **Examples follow the tested shapes.** The three worked URLs cover the same
  ground as the T16 table cases — host/port position, several variables across
  credentials, and a variable adjacent to literal text — so "documented
  examples match the implementation's actual behavior" is checkable against
  `TestLoadEnvInterpolation` rather than prose. The doc examples vary the exact
  variable count (examples 1–2 keep the port literal) while staying within
  behavior the tests exercise.
- **No default syntax stated as rejection.** `${VAR:-fallback}` has its whole
  span `VAR:-fallback` read as the name, fails `[A-Za-z_][A-Za-z0-9_]*`, and is
  rejected as malformed — so the doc says it is "not parsed and rejected as
  malformed", not "unsupported".
- **Reload line cites ADR-0015.** A changed expansion is one removed plus one
  added backend (identity is `(name, URL)`), the T16 reload test and the spec's
  Reload-semantics bullet; a one-clause reference keeps the operator-facing doc
  honest without restating the ADR.
