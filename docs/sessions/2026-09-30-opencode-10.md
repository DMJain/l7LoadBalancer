## Decisions

- `finish_time` is an `EXIT` trap, not a line at the end of `main`, so a slice
  that aborts (the CPU-pinning checks `exit 1`) still finalizes its record.
- `vegeta_version` is the pinned source tag `v12.13.0`, not `vegeta -version`:
  the image is built with `go install`, so the binary prints an empty Version.
  The pin is the authoritative version the rig runs.
- Runtime-only fields are gathered at start too, so a re-run over a live stack
  gets a complete record immediately; they stay null when the container is not
  up. The final write always refreshes them.
- `git_dirty` excludes `bench/results/`, the harness's own output. Without that,
  the first invocation's record makes the second invocation see an untracked
  file and report dirty on an otherwise clean tree (raised by the Standards
  review). The published run starts from a fresh clone, so this is neutral there.
- The spec's "every invocation" excludes `--help` and an unknown slice: those are
  not runs and a record for them would be misleading. `git_dirty` for a real run
  is unaffected.
- No new helper beyond the functions above; no ADR.
