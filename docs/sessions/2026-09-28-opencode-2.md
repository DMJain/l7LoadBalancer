## Design decisions

- **Seam** — one expansion pass inside `Load` between decode and return, in
  `expandBackendURLs`, delegating each URL to `expandEnv`. `Validate` and every
  consumer then see only resolved values; the resolved URL naturally flows
  through the existing `validateBackendURL` at `Validate` time, so a typo in an
  expanded value fails exactly like a literal typo with no second validation
  site.
- **Scanner** — a single left-to-right pass over the URL; `${` starts a
  reference, the first `}` ends it. No reference (`strings.Contains(raw, "${")`
  false) returns `raw` unchanged. A `$` not followed by `{` is literal. This is
  the minimum parser for the frozen syntax; no regexp backtracking needed beyond
  the name check, which reuses a small `envVarNamePattern`.
- **Failure wording** — errors name the backend and, for unset/empty, the
  variable; the expanded value is never written into an error. Malformed errors
  quote the offending template `${...}` (spec: the template is not a secret and
  may be quoted; the resolved value must not be). `expandEnv` returns
  un-prefixed errors so `Load`'s single `config: load %s: %w` wrap produces one
  `config:` prefix, matching the decode path.
- **Redaction boundary** — deliberately *not* changing `validateBackendURL`.
  Its messages still embed the raw (resolved) URL; that is exactly S4.T17's
  ticket ("validation errors never contain the expanded URL"), which is blocked
  by this one. No scope creep.
- **No ADR** — the bundle spec's ticket map records no ADR for T16; the
  decisions above are covered by the spec and recorded here per AGENTS.md
  Step 2.
