## The x/net dependency decision

The spec §6 and the ticket call for `golang.org/x/net/http2/h2c` and say to
"consider an ADR-0004 amendment" for the stdlib-only exception. Two findings:

1. **ADR-0004 is not a dependency ADR.** It is "Reject unimplemented algorithms
   in Validate"; the spec's cross-reference (repeated in the T1 session log) is
   stale. There is no stdlib-only ADR to amend. The "built entirely on the
   standard library" claim lives in `AGENTS.md`/`docs/architecture.md` and is
   about the request path; the project already carries prometheus/testify/yaml.
2. **The x/net dependency is genuinely required, not a shortcut.** Go 1.24+
   supports cleartext HTTP/2 in the stdlib via `http.Server.Protocols` +
   `SetUnencryptedHTTP2(true)`, which would avoid the dependency entirely —
   but `net/http`'s implementation (`maybeServeUnencryptedHTTP2`) detects
   **only the prior-knowledge `PRI * HTTP/2.0` preface**. It does not implement
   the HTTP/1.1 Upgrade handshake, and ticket 03 requires both. The deprecated
   `x/net/http2/h2c` handler implements both, which is why the spec chose it.

So: no ADR. The bundle spec is the decision record for this choice (same
position the T1 session took), and the dependency is explicitly mandated by the
ticket. The stdlib-only wording in `AGENTS.md`/`architecture.md` is left
unchanged as an open item below rather than edited unilaterally.

`golang.org/x/net` is pinned to **v0.57.0**, the newest release compatible with
the project's `go 1.25.1` directive. `@latest` (v0.59.0) requires Go 1.26 and
rewrites the `go` directive to `1.26.0`; that was rejected as an unrequested
toolchain bump. `go mod tidy` also records `golang.org/x/text v0.40.0` as
indirect (pulled by `x/net/idna`).

## What was built

- `go.mod`/`go.sum` — `golang.org/x/net v0.57.0` (direct),
  `golang.org/x/text v0.40.0` (indirect).
- `internal/app/app.go` — `Build` builds `clientHandler` per mode: plain and
  TLS return the proxy handler unchanged, h2c wraps it in

  `buildClientServer` becomes a `switch` over TLS/h2c/plain: TLS loads the cert
  pair, h2c leaves `TLSConfig` nil and `ReadTimeout` 0, plain sets `ReadTimeout`
  from config. `serve`'s and `buildClientServer`'s doc comments are updated.
- `internal/config/config.go` — the `H2C` field's doc no longer claims the
  handler chain is deferred; it now points at `app.Build`'s wrap.
- Tests `internal/app/h2c_test.go`:
  - `TestBuildH2CModeServerConstruction` — h2c server has no `TLSConfig`,
    `ReadTimeout` 0, `IdleTimeout` from config; metrics/health stay plain; an
    HTTP/1.1 request through `Handler()` still returns 200 (pass-through).
  - `TestRunH2CListenerServesHTTP2PriorKnowledge` — real `Run` on a free port;
    `http2.Transport{AllowHTTP: true}` with a plaintext `DialTLSContext` (which
    sends the preface, not an Upgrade) returns `resp.Proto == "HTTP/2.0"` and
    the backend body.
  - `TestRunH2CListenerUpgrade` — a raw `GET` with `Connection: Upgrade,
    HTTP2-Settings`, `Upgrade: h2c`, and an `HTTP2-Settings` value is answered
    `101 Switching Protocols`.
