## Decisions

- **The two windows come from vegeta, not awk.** `reload_window_reports`
  re-encodes each window's CSV slice to gob and asks `vegeta report` for the p99,
  so the judge's percentiles are the same computation as every other p99 in the
  results and no percentile is reimplemented in awk.
- **`non_2xx` and `transport_errors` are disjoint.** Transport errors are status
  0, which the old non-2xx filter swallowed. The scan keeps the total
  (`drops = errors`) for the informational field but peels transport out for the
  verdict, so one transport failure names `transport_errors` alone rather than
  both criteria (folded in from the two-axis review).
- **The verdict rides in the load cell.** The ticket wants the summary table to
  show it; `sighup-noop:PASS` extends the existing `load=` token convention
  without reformatting the shared summary table for every slice. Ticket 15 will
  reuse the same shape.
- **Window edge is the literal T+30 s**, not the measured `event_offset`. The
  spec says "T+30 s" and the dynamic offset is recorded alongside for the reader;
  a tens-of-ms sliver at the crossing is immaterial to a p99 over a ~30 s window.
- **No Go, no backend, no Nginx, no config change.**
