## S3.T5.3 — Health transition log lines (issue 04)

### Goal

Give `internal/health`'s two subsystems their first `slog` lines, edge-triggered
so a sustained failure/success streak logs exactly once per genuine transition
rather than once per probe or per request: the active checker emits
`event=health_ejected, reason=probe_failures` (WARN) and

### Decisions

- **The log gate is exact-equality AND genuine-state.** Issue 04 named the
  `== threshold` gate (distinct from the `>=` the `Mark*` calls use). On its own
  that gate still emits `health_reinstated` for a backend that never left the
  healthy state (every backend's first M successful probes at startup, since
  `NewRegistry` starts healthy) and `health_ejected` for a backend already
  ejected by passive detection. This was raised with the owner during the
  session; the agreed resolution was to add a state guard
  (`IsHealthy()`/`!IsHealthy()`, read before `Mark*` mutates it) so the line
  describes a genuine transition, matching ADR-0013 decision 11's "once per
  genuine transition" wording. The exact-equality gate is retained as
  specified. The guard reads `Backend`'s existing atomic health, so no new
  prober field is added, and because `Mark*` is idempotent no genuine
  transition can be missed (an episode that never changed state has no
  transition to log).
- **Log after `d.eject(b)` in the detector, before `Mark*` in the checker.**
  In the detector the shared `ejected` flag is already the edge trigger, so the
  line sits in that block; in the checker the state guard must read health
  before `Mark*` mutates it, so the line is emitted before the idempotent
  store.
- **Field names stay string literals; values come from `internal/logger`.** The
  `event`/`reason` values use the `logger.Event*`/`logger.Reason*` constants
  from issue 03; the field names (`backend`, `event`, `reason`) follow the
  existing literal convention, as in `proxy`. `internal/health` importing the
  `internal/logger` leaf adds no cycle risk.
- **No new ADR.** ADR-0013 decision 11 records the edge-triggered health
  logging decision; this ticket implements it. The state guard is the
  "genuine transition" clause of that same decision, not a new one.
- **`log` as the field name, `log` as the constructor parameter.** `internal/health`
  imports the `internal/logger` package for constants, so a `logger` field
  would be shadowed/confusing at the call site; `log` matches `main.go`'s local.
