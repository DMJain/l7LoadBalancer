### Decisions

- **The log gate is exact-equality AND genuine-state.** Issue 04 named the
  `== threshold` gate (distinct from the `>=` the `Mark*` calls use). On its own
  that gate still emits `health_reinstated` for a backend that never left the
  healthy state (every backend's first M successful probes at startup, since
  `NewRegistry` starts healthy) and `health_ejected` for a backend already
  ejected by passive detection. This was raised with the owner during the
  session; the agreed resolution was to add a state guard
  (`IsHealthy()`/`!IsHealthy()`, read before `Mark*` mutates it) so the line
  describes a genuine transition, matching ADR-0013 decision 11's "once per
  genuine transition" wording. The exact-equality gate is retained as
  specified. The guard reads `Backend`'s existing atomic health, so no new
  prober field is added, and because `Mark*` is idempotent no genuine
  transition can be missed (an episode that never changed state has no
  transition to log).
- **Log after `d.eject(b)` in the detector, before `Mark*` in the checker.**
  In the detector the shared `ejected` flag is already the edge trigger, so the
  line sits in that block; in the checker the state guard must read health
  before `Mark*` mutates it, so the line is emitted before the idempotent
  store.
- **Field names stay string literals; values come from `internal/logger`.** The
  `event`/`reason` values use the `logger.Event*`/`logger.Reason*` constants
  from issue 03; the field names (`backend`, `event`, `reason`) follow the
  existing literal convention, as in `proxy`. `internal/health` importing the
  `internal/logger` leaf adds no cycle risk.
- **No new ADR.** ADR-0013 decision 11 records the edge-triggered health
  logging decision; this ticket implements it. The state guard is the
  "genuine transition" clause of that same decision, not a new one.
- **`log` as the field name, `log` as the constructor parameter.** `internal/health`
  imports the `internal/logger` package for constants, so a `logger` field
  would be shadowed/confusing at the call site; `log` matches `main.go`'s local.

### Decisions

- **Add `Reopened` as a fifth `CircuitTransition` value (owner-approved).**
  The ticket and ADR-0013 decision 10 named four values, but the ticket's four
  log reasons include two that both end in Open (`consecutive_failures` from
  `Closed→Open`, `trial_failure` from `HalfOpen→Open`). A four-value enum
  carrying only the resulting state cannot tell the breaker which reason to
  log; ADR-0013's own "`circuit_half_opened`-via-`trial_failure`" phrase was
  the same inconsistency. Raised with the owner before coding; the agreed fix
  is a fifth value so each reason maps 1:1 to a transition. ADR-0013 was
  amended in place (no new ADR number) with a dated amendment section.
- **`CircuitAllow` reports `CircuitHalfOpened` only when it performs the
  promotion.** The promotion flag from `currentCircuit` is local to the call,
  so a `Registry.Selectable()`-scan-won promotion (the common production case,
  since every `Select()` scans before `Allow`) is never logged — preserving
  ADR-0013 decision 13's documented, permanent gap. Only the call that both
  promotes and takes the trial logs. A lock-free race where the promoter loses
  the trial CAS to another goroutine can also miss the line; this is the same
  class of accepted CAS race as ADR-0012's stale-while-Half-Open note.
- **`internal/backend` gains no import.** `CircuitTransition` is a plain
  `int`-backed type; the logging stays in `circuit`, which already imports
  `backend`. The `circuit` package imports the `internal/logger` leaf for the
  `Event*`/`Reason*` constants, adding no cycle risk.
- **Levels follow ADR-0013 decision 12.** `circuit_opened` (both reasons) at
  WARN; `circuit_closed` and `circuit_half_opened` at INFO.
- **No new ADR number.** ADR-0013 decisions 10/12 are the design; the
  fifth-value correction is an amendment to decision 10, not a new decision.

## S3.T6.1 — Whole-request metrics: counter + histogram (issue 06)

### Goal

Wire `lb_requests_total` and `lb_request_duration_seconds` into
`proxy.ServeHTTP`'s existing `start := time.Now()` / deferred `logRequest`
location, so every exit path — success, no-healthy-backend 503, circuit-denied
503, and `ErrorHandler` 502 — is counted and timed with the correct
`backend`/`method`/`status_class` labels, using `backend=""` only when no
backend was chosen. No gauges, no startup seeding, no Grafana stack (those are
issues 07–10). Decision already recorded in ADR-0013 decision 14; no new ADR.

### Done

- Task: S3.T6.1 (issue 06), recorded in `PROGRESS.md`.
- Commits: `5359d84` (claim), `e678941` (Red tests), then this close-out.
- `internal/proxy/proxy.go`:
  - `Proxy` gains an optional `metrics *metrics.Collector` field, installed by
    a new additive `SetMetrics(*metrics.Collector)`. `New(reg, sel)`'s frozen
    two-argument signature is untouched, and no fan-out interface is added.
  - `ServeHTTP`'s deferred `logRequest` call becomes `defer
    p.completeRequest(r, state, start)`.
  - New `completeRequest` sequences `observeRequest` then the existing
    `logRequest`, sharing the same `start` and `state`.

    `Collector.ObserveRequest(backendName(state), r.Method, statusClass(state.status), time.Since(start))`,
    a no-op when no collector is installed. It uses the whole client-facing
    window, not `RoundTripObserver`'s backend-only measurement.
  - New shared `backendName(*reqState)` helper (also used by `logRequest`, so
    the label derivation cannot drift) and `statusClass(int)` (`status/100 +

  `TestProxyObservesWholeRequestOnEveryExitPath` — a table over the four exit
  paths asserting both `lb_requests_total` (value 1) and
  `lb_request_duration_seconds` (sample count 1, positive sum, provisional
  buckets) exist under the exact expected label set, and that a request with a
  chosen backend is never also counted under `backend=""` — and
  `TestProxyWithoutMetricsCollectorServes` for the optional-collector no-op.
- `.scratch/s3-t4-t7-observability/issues/06-whole-request-metrics.md`:
  `Status: done`, boxes ticked, completion comment.
- `PROGRESS.md`: S3.T6.1 claimed then flipped `[DONE]`; current status and
  session-log entry updated.

### Decisions

- **Concrete `*metrics.Collector`, not a new interface.** Issue 06 allowed
  either a concrete collector or a small consumer-defined interface, and
  ADR-0013 decision 14 sanctions both. A concrete reference is the smallest
  thing that works and matches the ADR's posture of not adding an abstraction
  with one real implementation; `metrics` is a leaf, so `proxy` importing it
  adds no cycle. The ticket test seam (a real collector's private registry) is
  exercised directly.
- **One deferred completion hook, not a second mechanism.** `recordRequest`
  reuses `ServeHTTP`'s `start`/`state` and calls the unchanged `logRequest`, so
  the log line and the metric always describe the same request. `backendName`
  is shared between them rather than re-derived.
- **`statusClass` derived from `state.status`, not from the backend.**
  `status/100 + "xx"` produces `2xx`/`4xx`/`5xx`, matching `metrics/doc.go` and
  avoiding the unbounded cardinality a per-code label would create.
- **The histogram is the whole-request window.** `time.Since(start)` is
  deliberately not the observer fan-out's backend-round-trip duration
  (ADR-0013 decision 3).
- **No new ADR.** ADR-0013 decision 14 is the design; this is its
  implementation.

- **Out of scope, deliberately not built:** the `lb_active_connections`,

## S3.T6.2 — Active-connections gauge (issue 07)

### Goal

Wire `lb_active_connections` at the exact call sites `proxy` already uses to
maintain `Backend.ActiveConns()` — the dispatch `IncActive` and the
once-guarded response-body-`Close()` `DecActive` — so the gauge can never drift
from the real in-flight count, and seed every backend's series to `0`
immediately after `backend.NewRegistry` succeeds. No health/circuit gauges, no
Grafana stack (those are issues 08–10). Decision already recorded in ADR-0013
decisions 7 and 9; no new ADR.

### Done

- Task: S3.T6.2 (issue 07), recorded in `PROGRESS.md`.
- Commits: `2df8faa` (claim), `7cba958` (Red tests), then this close-out.
- `internal/proxy/proxy.go`:
  - `reqState` gains `metrics *metrics.Collector`, copied from `Proxy.metrics`
    in `ServeHTTP` (`state := &reqState{metrics: p.metrics}`), so `release()`
    can decrement the gauge without the release closures needing the `Proxy`.
  - New `activate()` (`IncActive` + `IncActiveConnections`) sits next to the
    existing once-guarded `release()`, which now also calls
    `DecActiveConnections`. `ServeHTTP`'s `b.IncActive()` becomes
    `state.activate()`; both are skipped when no collector is installed.
- `cmd/l7LoadBalancer/main.go`: the collector is constructed before
  `backend.NewRegistry`, and a new `seedMetrics(collector, reg)` is called
  immediately after it succeeds, setting every backend to `0` via
  `Collector.SetActiveConnections`.
- `internal/proxy/metrics_test.go`:
  `TestProxyActiveConnectionsGaugeTracksConcurrentInFlightRequests` — 100
  concurrent requests blocked in a real backend; asserts
  `Backend.ActiveConns()` and the gauge both read 100 in flight and both drain
  to 0 (mirrors S1.T6's leak-check, extended to the metric).
- `cmd/l7LoadBalancer/main_test.go` (new):
  `TestSeedMetricsActiveConnections` — builds a registry, seeds it, and asserts
  every backend's `lb_active_connections` series exists at `0` via
  `prometheus/testutil.GatherAndCompare`.
- `.scratch/s3-t4-t7-observability/issues/07-active-connections-gauge.md`:
  `Status: done`, boxes ticked, completion comment.
- `PROGRESS.md`: S3.T6.2 claimed then flipped `[DONE]`; current status and
  session-log entry updated.

### Decisions

- **Gauge inc/dec live in `reqState.activate()`/`release()`, next to the
  backend counter.** The ticket requires the same call sites as
  `IncActive`/`DecActive`; `reqState` already owns the once-guarded release, so
  holding the collector there (rather than threading the `Proxy` through the
  release closure) is the smallest change that keeps the two counts
  inseparable.
- **Seeding uses `SetActiveConnections(backend, 0)`, not Inc/Dec.** A
  Prometheus `Vec` metric materializes no series until first written, and the
  Inc/Dec pair cannot produce a `0` series — seeding with `Dec` would go to
  `-1`. ADR-0013 decision 9 explicitly names the setter for this
  ("...real transitions use `IncActiveConnections`/`DecActiveConnections`, so
  seeding its initial `0` uses `SetActiveConnections`"), so it is the same
  `Collector` method family real updates use, not a divergent seeding path.
- **`seedMetrics` is an extracted function so the startup seeding is
  testable.** `main()` calls `os.Exit` and is not directly testable; extracting
  the seeding loop gives the acceptance test a real seam without a subprocess.
  Issues 08/09 extend the same loop with the health and circuit setters.
- **`prometheus/testutil.GatherAndCompare` for the seed assertion.** The spec's
  Testing Decisions prefer `testutil` where a typed helper fits; comparing the
  whole `lb_active_connections` family is exactly its use case (unlike S3.T6.1,
  which needed single-series-by-label selection). This added
  `github.com/kylelemons/godebug` to `go.mod` as a test-only indirect dep of
  `client_golang`'s testutil; it was already present in `go.sum`, so no new
  download. `go.sum` is unchanged.
- **No new ADR.** ADR-0013 decisions 7 (wiring) and 9 (seeding) are the design;
  this ticket implements them.
