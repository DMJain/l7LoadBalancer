## S3.T5.2 — Canonical transition-log vocabulary (issue 03)

### Goal

Freeze the two new transition-scoped `log/slog` fields (`event`, `reason`) and
their closed, snake_case Go-constant value sets in `internal/logger`, so
S3.T5's producer tickets (issues 04/05) reference one shared vocabulary instead
of inventing overlapping values. No behavior change — nothing logs these fields
yet. ADR-0013 decision 12 already fixes the value sets; this ticket only
implements them.

### Decisions

- **Constants live in `internal/logger`, producers import it.** `internal/logger`
  is a leaf (no internal deps), so `internal/health`/`internal/circuit` gaining
  an import of it adds no cycle risk. This is where ADR-0013 decision 12 locates
  the vocabulary.
- **Value constants only; field names stay string literals.** The six existing
  request-scoped fields have no Go constants for their names, and the ticket
  asked only for the value sets. Introducing field-name constants now would be a
  new convention outside this ticket's scope.
- **No new ADR.** ADR-0013 decision 12 records the decision; this is its
  implementation.
- **Test the closed set, not just the values.** A typo'd or colliding value is
  exactly the failure this ticket exists to prevent, so the test pins values and
  asserts duplicate-freedom — cheap, and turns the "closed vocabulary" claim
  into a checked invariant.

### Scope boundary (AGENTS.md Step 2.5)

- **In scope:** `internal/logger/doc.go` field list; the two Go-constant value

- **Out of scope, deliberately not built:** the health/circuit transition log
