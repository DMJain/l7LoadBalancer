## Decisions

- **The hot-key section includes the core latency sweep, not just the peak
  throughput result.** Issue 12 records a distribution and owner/spill for every
  consistent-hash run at peak **and** every latency rate; issue 17 says "every
  consistent-hash result (core and degraded)". Parsing the per-rate blocks is
  what surfaces the bounded-loads story — the fixture shows `spill=no` at 30% of
  peak and `spill=yes` at 90%, the "spills once in-flight load exceeds the bound"
  claim in the narrative. The `Load` column keeps the rows distinguishable.
- **Backend-kill and the reloads get separate tables.** Their measurement sets
  are disjoint (a kill window versus reload p99 windows and a verdict); one
  wide heterogeneous table would carry mostly-empty cells. Splitting lets each
  row carry exactly its own fields.
- **The reload table carries both p99 windows.** The verdict is `post-p99 ≤
  factor × pre-p99`; printing only one p99 would hide the comparison the verdict
  is judged on.
- **The drain snapshot table prints raw counts, not deltas.** The result file
  records both; the raw counts are the evidence, and the judged delta
  (snapshot 3 − snapshot 2) is already in the verdict. Deltas stay in the result
  file the harness wrote.
- **No new ADR, no Go, no harness change.** The spec fixes the approach; the
  generator is a benchmark tool. `bench/run.sh` is untouched.
