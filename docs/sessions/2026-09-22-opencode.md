## Decisions

- **Log capture is a `slog.Handler`, not the JSON-buffer seam.** The existing
  packages capture JSON text because they are internal test packages; an
  external package cannot reach unexported seams, and `slog.Record` gives
  structured field access directly. `assertTransitionLogged` asserts exactly
  one match (the arcs' "exactly one" wording), with `transitionCount` exposed
  for the negative/baseline case.
- **Gauge reads go through `Registry().Gather()`, not `testutil.ToFloat64`.**
  `internal/metrics` keeps its instruments unexported, so the external package
  cannot name the target `GaugeVec`; gathering the registry is the same
  S3.T6.3-family path `testutil` wraps, and is the only read the collector
  exposes. No production accessor was added (the ticket forbids prod-code
  edits outside `internal/health`).
- **`Kill` closes the whole `http.Server`, not just the listener.** Closing
  only the listener leaves pooled keep-alive connections serving, so the
  health client and proxy transport would keep succeeding through a dead
  backend. `Server.Close` drops the listener and all live connections, giving
  the real `ECONNREFUSED` the arc needs.
- **`assemble` routes `slog.Default()` at the capture handler for the test's
  duration.** `proxy.New`'s frozen two-arg signature captures `slog.Default()`
  at construction, so request lines would otherwise spam the test output; the
  default is restored in cleanup.
- **Arc (iii) is deterministic because the circuit opens at 3 failures, below
  passive detection's 5-in-window threshold.** Three sequential round-robin
  selections of the 500 backend open its circuit and exclude it before passive
  detection can reach its own threshold, so the only ejection line is the
  active checker's `probe_failures` — the "one health transition log" the arc
  asserts.

  `[DONE]` gate (it was not present).

## Spec/architecture conflicts surfaced before implementation (owner-approved)

Orienting per AGENTS.md Steps 0–2 surfaced three of the ticket's acceptance
bullets that are **not reachable** against the frozen architecture. Each was
confirmed by tracing the code and by throwaway diagnostic tests before any
deliverable was written, then put to the owner, who chose "adapt to real
behavior" over closing the gaps in production code (which would need an ADR
outside the bundle's stated scope):

1. **`circuit_half_opened` + `lb_circuit_state{half_open}` never fire via the
   proxy.** `ServeHTTP` calls `Select()` first; `RoundRobin.Select` →
   `Registry.Selectable()` calls `gate.Open()` on every backend, which wins
   the lazy Open→Half-Open promotion CAS in `Backend.CircuitOpen`. By the
   time `Registry.Allow(b)` → `Breaker.Allow` → `Backend.CircuitAllow` runs,
   the promotion already happened and `promoted` is false, so it reports
   `CircuitNoChange` and writes nothing. This is exactly ADR-0013 decision
   13's documented, accepted, permanent gap. The tests therefore **pin** the
   gap (assert zero `circuit_half_opened` records) and prove the lazy,
   timer-free property through the trial's resolution — `circuit_closed`/
   `trial_success` or `circuit_opened`/`trial_failure` — firing on the
   post-cooldown request.
2. **"503 via `Registry.Allow` denial during cooldown" is unreachable through
   the proxy.** `Selectable()` filters open circuits, so `Select` never
   returns an open backend and `Allow` is never consulted for it. With the
   single test backend, a cooldown request is denied by
   `ErrNoHealthyBackends` — still a 503, still without touching
   `IncActive`/`lb_active_connections`, which is the contract ADR-0012
   actually guarantees. The test asserts that observable contract and does
   not claim the `Allow` path.
3. **The ticket's `probeInterval=20ms` fast path makes arcs (iv)/(v)
   impossible.** Active probes treat a 5xx as failure, so the 500-serving
   backend is health-ejected and drops out of `Selectable` before a half-open
   trial can ever be taken. T9 neutralizes the checker with a one-hour
   `probe_interval` (a config knob, ADR-0011 decision 10 — no production
   constant bent) and uses a **single backend** so round-robin's post-cooldown
   selection of the trial is deterministic.

No deviation warrants a lazy S3.T10 close-out, so Sprint 3 flips to complete.
