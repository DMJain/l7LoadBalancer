## Decisions

- **One-line fix, no new ADR.** The gate is a shipped-code drift from
  ADR-0011 decision 3, not a new decision; the amendment records it in place,
  exactly the pattern ADR-0006 set. The ADR table in `AGENTS.md` is unchanged
  (an amendment section is not a new row).
- **Failure gate deliberately left at `==`.** The `>=` change applies only to
  the success path. The failure gate's `== probeFailuresBeforeUnhealthy` was
  not part of the reported defect, and the consecutive-failure counter resets
  to zero on any success, so it cannot drift past N the way the uncapped
  success accumulator can. Changing it would be scope creep beyond the ticket.
- **Test asserts the log record, not the gauge.** The fix is at the checker
  layer; `lb_backend_healthy` is written from the same guarded block, and
  S3.T6.3 already verifies the observer→gauge wiring. The new test uses the
  existing `captureLogger`/`recordsWithEvent` seam in the same package and
  does structured field checks on `event`/`reason`/`backend`, never substring.
- **`require` for setup, `assert` for values**, matching every existing
  package.

## Decisions

- **Log capture is a `slog.Handler`, not the JSON-buffer seam.** The existing
  packages capture JSON text because they are internal test packages; an
  external package cannot reach unexported seams, and `slog.Record` gives
  structured field access directly. `assertTransitionLogged` asserts exactly
  one match (the arcs' "exactly one" wording), with `transitionCount` exposed
  for the negative/baseline case.
- **Gauge reads go through `Registry().Gather()`, not `testutil.ToFloat64`.**
  `internal/metrics` keeps its instruments unexported, so the external package
  cannot name the target `GaugeVec`; gathering the registry is the same
  S3.T6.3-family path `testutil` wraps, and is the only read the collector
  exposes. No production accessor was added (the ticket forbids prod-code
  edits outside `internal/health`).
- **`Kill` closes the whole `http.Server`, not just the listener.** Closing
  only the listener leaves pooled keep-alive connections serving, so the
  health client and proxy transport would keep succeeding through a dead
  backend. `Server.Close` drops the listener and all live connections, giving
  the real `ECONNREFUSED` the arc needs.
- **`assemble` routes `slog.Default()` at the capture handler for the test's
  duration.** `proxy.New`'s frozen two-arg signature captures `slog.Default()`
  at construction, so request lines would otherwise spam the test output; the
  default is restored in cleanup.
- **Arc (iii) is deterministic because the circuit opens at 3 failures, below
  passive detection's 5-in-window threshold.** Three sequential round-robin
  selections of the 500 backend open its circuit and exclude it before passive
  detection can reach its own threshold, so the only ejection line is the
  active checker's `probe_failures` — the "one health transition log" the arc
  asserts.
- **`shellcheck` installed via Homebrew** to satisfy the ticket's shell-half
  `[DONE]` gate (it was not present).

- **Arc (iii) does not exercise passive ejection.** The circuit opens at 3
  failures, below passive detection's 5-in-window threshold, so the circuit
  excludes the bad backend before passive can eject. This is a genuine
  inconsistency in the bundle spec's prose ("passive detection and active
  checker both eject on the same signal") rather than a test defect: with the
  frozen constants (circuit 3, passive 5) passive can never reach its
  threshold on a constant-500 backend. Arc (iii)'s own bullet — "one health
  transition log" — is only satisfiable by the active checker logging and
  passive being suppressed by the `IsHealthy()` guard. Passive detection stays
  covered at unit scope (S3.T2 and `internal/proxy/proxy_test.go`). The commit
  message's "combined passive/active ejection" wording overstated this; the
  test's actual claim (one signal drives both the health ejection and the
  circuit open) is accurate.
- **"Exactly one health transition" was reason-specific only.** A second
  ejection line with a different reason would have passed. Added
  `eventCount(event, backend)` and asserted exactly one `health_ejected` and
  exactly one `circuit_opened` for the backend regardless of reason.
- **Arc (i)'s "selector no longer chooses X" was vacuous.** It only checked
  the body was not `x.id`, which a still-selected dead backend (502) also
  satisfies. Strengthened to require status 200 on every request in the burst,
  which a selected dead backend cannot produce.

Acted on: the strengthened arc (i) and (iii) assertions, the
`requireGaugeEventually` helper collapsing the repeated poll shape, removal of
