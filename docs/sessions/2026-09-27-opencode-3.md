## Design decisions

No ADR: the ticket map marks T9 "none". The one production change is the
handler mux; everything else is tests.

- **A `ServeMux` on the metrics server, not a blank-import delegation.** The
  metrics handler was the bare `promhttp.HandlerFor(...)`, which answers *every*
  path with 200 and the metrics body. `buildMetricsHandler` returns a mux with
  `/metrics` plus the five explicit `pprof` endpoints (index, cmdline, profile,
  symbol, trace). Index serves the named profiles (`goroutine`, `heap`, …)
  as sub-paths, so no other routes are needed. The explicit registration is the
  `net/http/pprof` documented pattern for a custom mux; the package's
  `DefaultServeMux` side-effect registration is never served by this binary.
- **pprof shares the always-on, unauthenticated metrics listener.** No second
  port, no config field (ADR-0005 puts security hardening out of scope, and the
  attack surface is already accepted for `/metrics`).
- **The audit lives in `test/chaos` and reuses the harness.** `assemble`,
  `flippableBackend` (`ServeGated`, `Kill`), and the gauge helpers already exist
  for T5/T6/T8; the audit is a new scenario over them, not new machinery.
  `circuitChaosConfig` neutralizes the active checker (1h interval) so the only
  traffic is the burst the test drives.
- **Baseline captured after a warmup, via a settle loop.** The transport's
  idle-connection goroutines and the app's own startup goroutines must be in the
  baseline, not misread as leak growth. `settledGoroutines` polls until the
  count is stable for three ticks; `requireGoroutinesSettleToWithin` requires
  the same stability *below* the bound after the burst, so a transient dip
  cannot mask a settled leak.
