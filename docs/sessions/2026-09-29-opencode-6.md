## Implementation notes

- **Eight configs.** The seven new files mirror the existing http11 roundrobin.
  http11 configs are plain HTTP to `http://backendN:8080`; h2 configs select TLS
  by the `tls:` block (shared SAN cert at `/certs`) and point at
  `https://backendN:8080` with `force_http2: true`, `tls_skip_verify: true`.
  `internal/config/bench_configs_test.go` walks the explicit eight-path table
  through the real `Load`+`Validate` pipeline and locks the algorithm-per-
  filename mapping and the h2/http11 shape.
- **`bench/run.sh` is the parameter source of truth.** Seed/double/bisect peak
  discovery (seed 1000, granularity 500, `MAX_RATE` cap so a never-failing search
  terminates), p99/error thresholds, warmup, step, latency percent, failure
  parameters — all constants at the top. Slices `core` (36: h2, matched
  roundrobin/leastconn vs Nginx, solo consistent-hash/p2c-ewma), `protocol`
  (12: http11 roundrobin vs Nginx), `failure` (2), `all` (default).
- **Warmup without a vegeta flag.** vegeta has no warmup skip. Each measured
  attack runs `WARMUP_SECS` longer, then the leading results are dropped by
  filtering the CSV's Unix-nanosecond column. At ~1.8e18 ns a double loses
  ~256 ns, far below the 5 s window, so the boundary is exact for any practical
  purpose; the reasoning is in the script header.
- **Results and summary.** `.txt` (a metadata comment + the vegeta text report)
  and `.hdr` (`report -type=hdrplot`) under `bench/results/<slice>/`, filenames
  parameter-encoded. Metrics are parsed from `report -type=json` with `grep -o`;
  each slice prints an aligned summary table. `results/.tmp/` holds raw
  `.gob`/`.csv` scratch and is gitignored.
- **Failure mode.** Steady state is TLS+HTTP/2 round-robin at 50% of peak for
  60 s (spec §29). `backend-kill` stops `backend3` at T+30 s; `sighup` sends an
  unchanged-config reload. `docker compose kill -s HUP lb` is the host form of
  the ticket's `kill -HUP 1`: the distroless image has no shell/`kill`, and the
  LB is PID 1 (ADR-0019). Both runs tee the attack into a 1 Hz cumulative-JSON
  time series for time-to-detection / p99-recovery / drops.

### Three fixes the live smoke forced

1. **`bench/run.sh` config path.** `set_lb "configs/h2/x.yaml"` (no `./`) made
   compose treat the bind source as a *named volume*: `refers to undefined
   volume ...: invalid compose project`. Fixed to `./configs/...`.
2. **`LB_CONFIG` must be the exported global.** `set_lb` originally used a
   command-prefix assignment, so the next `docker compose run vegeta` re-read the
   *old* exported `LB_CONFIG` and recreated the LB on the default config
   mid-slice. The LB scenarios then failed TLS while Nginx passed. Fixed by
   assigning the exported global.
3. **The h2 slice's Nginx and health checker.** Issue 05's `h2.conf` proxied
   plaintext to backends that now serve TLS, so Nginx returned Go's 400 "Client
   sent an HTTP request to an HTTPS server"; fixed to `proxy_pass https://backends`
   with `proxy_ssl_verify off` (nginx has no upstream-HTTP/2 directive here, so
   the backend leg is TLS+h1 for Nginx and TLS+h2 for the LB; the client-facing
   comparison stays matched). Separately, the active health checker uses its own
   default-cloned transport (ADR-0011 d11) that `tls_skip_verify` cannot reach,
   so the compose `lb` service sets `SSL_CERT_FILE=/certs/server.crt`; otherwise
   every backend is ejected after three failed probes. Both are documented in the
   configs/README.
