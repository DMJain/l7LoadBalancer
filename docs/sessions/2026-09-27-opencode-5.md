## Design decisions

The ADR *is* the deliverable, so no separate design record. Numbering: ADR-0018
(0017 is the highest). Style follows ADR-0015–0017 (Context / Decision with
numbered or headed sub-decisions / Consequences / Alternatives considered).

The decision's spine, each point tied to live code rather than assertion:

- **One client request = one slot = one observer outcome.** `activate()`
  (`proxy.go:86`) claims the slot on both the backend counter and the gauge;
  `release()`'s `sync.Once` (`proxy.go:95`) enforces exactly-once across the two
  triggers (body `Close`, `errorHandler`); `observe()` (`proxy.go:242`) fans one
  outcome out to circuit/outlier/EWMA.
- **The two harms.** A retry double-counts `ActiveConns` — the very metric
  `LeastConnections` (`leastconn.go:37`) and `ConsistentHashBoundedLoads`
  (`consistent_hash.go:24,159`) select on — and feeds a second failure into the
  outlier window and a second 2s EWMA penalty (`proxy.go:30`) for one logical
  failure.
- **Why it cannot simply be added later.** Request bodies are consumed streams
  (no replay without buffering, which regresses ADR-0007's streaming posture),
  and idempotency is unknowable to a method-agnostic, body-opaque LB — so retry
  is the client's to own, which is exactly what S4.T5's 499 tiers and T8's
  bounded timeouts leave room for.
- **A stdlib nuance recorded as a distinction, not an alternative:** Go's
  `http.Transport` already retries idempotent requests that failed to reuse a
  connection, before anything is written to a backend; that is invisible to the
  observer fan-out and does not contradict this decision.
