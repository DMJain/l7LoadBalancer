# 05: Benchmark infrastructure (compose + backends + Nginx)

**What to build:** `docker compose up` brings up the full benchmark topology: the LB, Nginx (pinned 1.27.x), 4 dummy backends, and a vegeta container — all on a single flat bridge network. The dummy backends serve configurable response sizes (`/200b`, `/10kb`, `/1mb`) and a `/health` endpoint, and optionally serve TLS (with HTTP/2 via ALPN) when `TLS_CERT_FILE`/`TLS_KEY_FILE` env vars are set. Two Nginx configs exist: plain HTTP and TLS+HTTP/2, both with matched algorithm, topology, and keepalive settings mirroring the LB. The cert script output is volume-mounted into TLS-enabled containers.

**Blocked by:** 03 (h2c support), 04 (HTTP/2 to backends)

**Status:** ready-for-agent

- [ ] Dummy backend extended with `/200b` (200 bytes), `/10kb` (10 KB), `/1mb` (1 MB) endpoints serving pre-generated byte slices
- [ ] Dummy backend extended with `/health` endpoint (200 OK, minimal body) for the LB's health checker
- [ ] Dummy backend TLS: `TLS_CERT_FILE` and `TLS_KEY_FILE` env vars trigger `ListenAndServeTLS`; unset means `ListenAndServe`. Consistent with existing `SLEEP_MS`/`FAIL_RATE` pattern.
- [ ] Dummy backend does NOT set `TLSNextProto` to empty map — that silently disables HTTP/2 server-side (same class of gotcha as `ForceAttemptHTTP2` on the client)
- [ ] Existing dummy backend features preserved: `-name`, `-addr` flags, `SLEEP_MS`, `FAIL_RATE` env vars
- [ ] Docker-compose with services: `lb`, `nginx`, `backend1`–`backend4`, `vegeta`
- [ ] Single flat bridge network; LB and Nginx publish ports; vegeta, backends internal
- [ ] Nginx pinned to 1.27.x; uses `http2 on;` directive (not deprecated `listen ... http2;`)
- [ ] Two Nginx configs: `bench/nginx/http11.conf` (plain HTTP) and `bench/nginx/h2.conf` (TLS+HTTP/2)
- [ ] Nginx configs use matched algorithm, backend count, and keepalive settings — constrained match, not "Nginx at its best"
- [ ] Vegeta runs in-compose (`docker compose run vegeta ...`), not on host
- [ ] Cert script output volume-mounted into TLS-enabled containers
- [ ] `docker compose up` brings all services up healthy
